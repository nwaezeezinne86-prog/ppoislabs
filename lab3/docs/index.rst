1. Цель работы
--------------

Спроектировать и реализовать крупный объектно-ориентированный проект на
тему «Приложение для отслеживания фитнеса», удовлетворяющий количественным
требованиям:

- не менее 50 классов;
- не менее 150 полей суммарно;
- не менее 100 уникальных поведений;
- не менее 30 ассоциаций между классами;
- не менее 12 собственных исключений.

Дополнительно: консольный интерфейс, unit-тесты с покрытием > 90 %,
документация Sphinx, CI/CD-конвейер.

3. Выбранный язык и инструменты
-------------------------------

- Язык программирования: **Python 3.10+**
- Модульное тестирование: **unittest**, покрытие — **coverage**
- Статический анализ: **ruff**

стандартная библиотека Python.

   │   ├── health.py       # пульс, сон, шаги, вода
   │   ├── nutrition.py    # еда, приёмы пищи, рецепты
   │   ├── social.py       # друзья, челленджи, лента
   │   └── users.py        # аккаунты, профили, подписки
   ├── tests/              # unit-тесты (unittest)
   ├── docs/               # эта страница Sphinx

   ├── cli.py              # консольное меню
   ├── pyproject.toml      # конфигурация пакета и линтера

Проект разделён на три уровня:

- **Предметный уровень** — все модули ``fitness/``, без ввода-вывода.
- **Уровень представления** — ``cli.py``, работает через фасад
  ``FitnessApp``.
- **Уровень тестирования** — ``tests/``, тесты только через публичное API.

8. Консольный интерфейс
-----------------------

``lab3/cli.py`` — меню из девяти пунктов, полностью отделённое от
предметной модели. Все операции выполняются через фасад ``FitnessApp``.

Пункты меню:

1. Регистрация пользователя.
2. Вход в систему.
3. Запись силовой тренировки.
4. Запись пробежки.
5. Запись приёма пищи.
6. Установка цели по весу.
7. Отчёт за неделю.
8. Создание челленджа и присоединение к нему.
9. Таблица лидеров.

Запуск:

.. code-block:: bash

   python cli.py

9. Тестирование
---------------

Все модули покрыты тестами на **unittest**. Покрытие проверяется
инструментом **coverage**.

.. code-block:: bash

   python -m unittest discover -s tests -t .
   coverage run -m unittest discover -s tests -t .
   coverage report --fail-under=90

Требование — покрытие не менее 90 %.

10. Документация
----------------

Документация сгенерирована Sphinx с расширениями ``autodoc``,
``napoleon`` и ``viewcode``. Файл ``docs/conf.py`` добавляет корень
проекта в ``sys.path`` и включает перечисленные расширения.

Сборка:

.. code-block:: bash

   pip install sphinx
   python -m sphinx -b html docs docs/_build/html

Результат: ``docs/_build/html/index.html``.

11. Непрерывная интеграция
--------------------------

Пайплайн ``.github/workflows/lab3.yml`` запускается при каждом push в
``lab3/`` и включает четыре задачи:

- **test-and-lint** — статический анализ (ruff) и тесты с проверкой
  покрытия (coverage, порог 90 %);
- **build** — сборка wheel и sdist;
- **docs** — сборка HTML-документации Sphinx;
- **release** — публикация артефактов при пуше тега ``lab3-v*``.
